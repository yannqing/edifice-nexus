# [v0.5] OA 阶段二实现说明

> 编写时间：2026-05-06
> 范围：请假、出差、补卡、外出、转正、离职、通用审批接入统一申请单与审批流。

## 一、交付内容

阶段二把第一阶段的 `oa_application` 从“申请数据草稿”推进到“可提交、可审批、可流转”的流程底座。

已覆盖申请类型：

- 通用审批
- 请假
- 出差
- 补卡
- 外出申请
- 转正申请
- 离职

## 二、后端流转

新增审批业务类型：

- `ApprovalBizType.OA_APPLICATION`
- `biz_type_ext = oa_application`

申请提交时：

1. 校验申请是草稿。
2. 校验首审人。
3. 调用 `ApprovalFlowService.submit(...)` 创建第一条待审批记录。
4. `oa_application.status` 更新为 `1 审批中`。
5. `oa_application.current_record_id` 保存当前待审批记录。

审批时：

1. 审批人调用 `POST /oa/application/approve`。
2. 通过且传入 `nextApproverId`：创建下一级审批节点，申请仍为审批中。
3. 通过且不传 `nextApproverId`：视为终审通过，申请状态更新为 `2 已通过`。
4. 驳回：申请状态更新为 `3 已驳回`。
5. 申请人撤回：当前审批记录标记拒绝，申请状态更新为 `4 已撤回`。

## 三、前端能力

`/oa/applications` 支持：

- 我的申请
- 草稿
- 审批中
- 待我审批
- 已结束

新建申请时，7 类阶段二流程使用结构化字段，不再要求用户手写 JSON。

## 四、后续阶段衔接

阶段三开始，用章、用车、公文会复用当前审批流，再补专用资源表：

- 印章档案
- 车辆档案
- 公文附件与密级字段

阶段四财务类申请会在当前 `form_data` 基础上增加明细表或明细 JSON 校验。
