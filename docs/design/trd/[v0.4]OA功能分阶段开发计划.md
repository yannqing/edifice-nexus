# [v0.4] OA 功能分阶段开发计划

> 编写时间：2026-05-06
> 目标：在现有 edifice-nexus 与已部署的 Edifice OA 底座上，逐步补齐人事、行政、财务、项目协同类 OA 能力。考勤定位 / 拍照打卡最后处理，优先评估钉钉或企业微信考勤 API。

## 一、总体原则

- edifice 继续作为用户、账号、组织信息的主系统。
- OA 侧用户只做镜像，不在 OA 侧维护用户、角色、部门、岗位。
- 申请单先在 edifice 中统一沉淀业务数据，再按阶段接入 OA/Flowable 审批流。
- 通用字段、附件、审批状态、申请人、审批人等能力抽象为统一申请单模型，避免每个流程重复造表。
- 考勤类功能最后做，优先对接钉钉/企业微信成熟考勤能力，自建打卡仅作为备选。

## 二、阶段划分

### 阶段一：OA 集成底座与申请中心骨架

交付范围：

- OA SSO 入口：edifice 登录后点击 OA 不再二次登录。
- OA 用户同步：edifice 新增、修改、删除、Excel 导入用户后自动同步到 OA 镜像表。
- OA 申请中心第一版：
  - 支持申请类型元数据。
  - 支持创建、保存草稿、提交、撤回申请。
  - 支持“我的申请”列表与详情字段。
  - 先承载通用审批、请假、出差、补卡、外出、转正、离职、用章、用车、公文、采购、报销、付款、开票等类型的统一表单数据。

验收标准：

- edifice 侧边栏有“OA 申请”入口。
- 用户可以创建至少一种申请草稿并提交。
- 数据落入 `oa_application` 表。
- 后续具体流程可以在该表基础上接审批引擎。

### 阶段二：人事行政类流程

交付范围：

- 请假、出差、补卡、外出申请。
- 转正申请、离职申请。
- 通用审批。
- 基于统一申请单接入审批流：提交后生成审批记录，审批通过/驳回后回写申请状态。

验收标准：

- 申请人可提交。
- 审批人可在待办中看到并处理。
- 申请状态流转完整。

### 阶段三：资产与行政资源流程

交付范围：

- 用章申请：新增印章类型/印章档案，申请时选择印章。
- 用车申请：车辆档案、附件上传。
- 公文审批：正文、附件、密级、紧急程度。

验收标准：

- 印章、车辆可维护。
- 申请可关联资源档案和附件。
- 审批链完成后资源使用记录可追溯。

### 阶段四：财务与采购流程

交付范围：

- 采购申请：采购明细行、供应商、金额汇总。
- 费用报销：报销明细、票据附件。
- 对外付款：收款方、账户、金额、合同附件。
- 开票申请：抬头、税号、开户行、开票项目、金额。

验收标准：

- 明细行可增删改。
- 金额自动汇总。
- 附件与审批记录完整保存。

### 阶段五：项目成果与验收协同

交付范围：

- 阶段性验收与现有项目验收模块联动。
- 成果文件归档、成果提交审批。
- 与项目阶段、项目文件、产值分配形成闭环。

验收标准：

- 项目阶段完成后可发起成果/验收相关 OA 流程。
- 审批通过后自动更新项目侧状态。

### 阶段六：考勤

优先方案：

- 对接钉钉/企业微信考勤 API，定时同步考勤记录。
- 补卡审批通过后回写考勤异常处理结果。

备选方案：

- 自建移动端 H5/uni-app 打卡页，支持定位、拍照、地理围栏和异常申诉。

验收标准：

- 考勤记录可查询。
- 补卡审批与考勤异常记录联动。

## 三、阶段一数据模型

`oa_application` 作为统一申请单主表：

- `application_id`：申请单 id。
- `application_no`：申请编号。
- `application_type`：申请类型，如 `leave`、`business_trip`、`seal`。
- `title`：申请标题。
- `applicant_id`：申请人。
- `status`：0 草稿，1 审批中，2 已通过，3 已驳回，4 已撤回。
- `priority`：0 普通，1 重要，2 紧急。
- `form_data`：JSON 表单内容。
- `attachment_ids`：JSON 附件 id。
- `submitted_time`、`approved_time`：提交/终审时间。

第一阶段不强绑定某个固定表单字段，先通过 `form_data` 支撑多申请类型，第二阶段开始再对高频流程做强校验和专用字段。

## 四、后续扩展点

- 审批链：复用现有 `approval_records`，或按 OA/Flowable 流程定义接入。
- 附件：复用现有文件上传体系。
- 部门：短期使用 edifice 用户字段；中期把部门/项目组织能力迁入 edifice 后再同步到 OA。
- 移动端：先做响应式 H5，考勤阶段再评估 uni-app 或钉钉内应用。
