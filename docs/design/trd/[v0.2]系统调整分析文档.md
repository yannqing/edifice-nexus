## 二、笔记解读与业务重识

### 2.1 产值的本质

> 产值 = 活干了（活的价值），与收款无关。

结论：**产值分配与回款必须解耦**。回款仍是独立模块（记录现金回流），但**报表、统计、仪表盘里凡是"回款率"字段一律删除**；产值"完成"的判定从"已发放"切换为"分配单已审批 / 已确认"（见 §4.2）。

### 2.2 分配规则（来自 QA 段）

- **公司留存：40%**（归公司及领导层）
- **个人正常分配：8.06%**（做得好的情况）
- **个人分配下限：4%**（做得不好，差额 4.06% 留给领导）
- 成员**离职**后：后续不再分配；**项目结算时如有金额未发给离职成员，统一归集到"其他金额"** 字段，保证项目账面自洽。

### 2.3 分配维度

- 按**季度 × 项目阶段**分配：某季度某阶段可能金额为 0；
- **公司补贴**：只记录，不计入产值；
- 输入的是"**分配比例 + 完成比例**"，金额由系统算出：
  `金额 = 合同金额 × 阶段产值比例 × 分配比例 × 完成比例`
- 报表要能汇总到"**人员分配汇总表（季度）**"。

### 2.4 绩效还原

- 按季度还原金额，**当季度全部还完**；
- 前期先做"还原分配"，工资明细 / 工资管理暂不做；
- 财务录入实发工资（绩效、社保等），后续再接入。

### 2.5 角色调整

新增：**公司领导**（接收 40% 中超出个人实得的那部分）。现有角色体系需显式化角色 code，并把这个角色参与到产值分配时的"兜底接收人"逻辑中。

业务角色参考（笔记）：

- 总经理
  - 总工
  - 项目经理
  - 业务部经理
    - 安装总管
    - 组建总管
- （新）公司领导 — 产值兜底接收人
- （现有）项目经理 / 项目成员
- （新）专业主管、总工 — 用于项目文件多级审批

### 2.6 项目文件多级审批

- 任意成员均可上传；
- 一级：**项目负责人**（选下一级审批人）；
- 二级：**专业主管**（选下一级审批人）；
- 三级：**总工**；
- 对应到：`approval_records.approval_record_type = 0`（项目文件上传），已有枚举，但**链式审批（每一步指定下一个人）**未实现。

### 2.7 新增模块清单

1. **投标管理**（独立于项目，含附件、状态、审批、看板）；
2. **公告**（已有表，缺 Controller + 前端页面）；
3. **成果 / 过程 / 阶段性验收**（审批）；
4. **资料库管理**（跨项目的资料聚合）；
5. **绩效模块**（原"财务管理"入口重命名为"绩效"，先实现"还原分配"）。

### 2.8 明确删除 / 下线

- 所有"**回款率**"相关字段 & 统计（表、VO、前端卡片）；
- 现 `output_value.status` 中的"已发放"语义不再等同于"产值完成"，需要重新定义（见 §4.2）。

## 三、差异矩阵（要做什么）

| 维度 | 现状 | 目标 | 动作 |
| --- | --- | --- | --- |
| 产值 vs 回款 | 深度耦合（Dashboard 把"完成产值"=已发放） | 完全解耦 | 改报表口径；删除"回款率" |
| 产值分配维度 | `output_value_id ↔ project_stage_id` | 季度 × 阶段 | 新增 `quarter` 字段（`YYYY-Qn`） |
| 分配比例 | 单一 `ratio` | `alloc_ratio` + `completion_ratio` | 拆字段，金额由公式计算 |
| 公司留存 | 无 | 40% 公司 / 个人 8.06% or 4% / 差额给领导 | 新增分配类型枚举 + 领导兜底逻辑 |
| 离职兜底 | 无 | 项目结算时差额归"其他金额" | 新增字段 + 结算逻辑 |
| 公司补贴 | 无 | 只记录不计入产值 | 新增补贴表 / 字段 |
| 绩效还原 | 无 | 季度还原，当季度还完 | 新增 `performance_restore` 相关表 |
| 角色 | 仅 `sys_role` 基础表 | 新增"公司领导"/"专业主管"/"总工" | 初始化角色数据（等系统上线阶段） |
| 项目文件审批 | `approval_records` 无链式 | 三级链式（项目负责人→专业主管→总工）| 新增 `next_approver` + `level` 字段 |
| 验工单审批 | 单次审批 | 支持"指定下一级"（对齐笔记中 mermaid） | 复用项目文件多级审批逻辑 |
| 资料库 | 无独立入口 | 跨项目资料聚合 | 基于 `files` + 分类 + 权限 |
| 公告 | 无 Controller/页面 | 完整 CRUD + 展示 | 补 API + 前端 |
| 投标管理 | 无 | 完整模块 | 新表 + API + 前端 + 看板 |
| 成果 / 过程 / 阶段性验收 | 无独立模型 | 三种单据，均走审批 | 新表 + API |
| 工时 | 简单 CRUD | 额定工时 + 审批 | `timesheet` 加 `status` 细分 + 审批流 |
| 导航 | "财务管理" | "绩效" | 前端侧边栏重命名 |

### 4.2 字段 & 枚举语义调整

- `output_value.status` 的"3-已发放"含义改为：**"产值确认完成（可并入绩效还原池）"**，不再等同"现金已发"；
- 建议新增 `output_value.confirmed_time` 作为新口径的完成时间，保留 `paid_time` 以兼容；
- `CollectionRecord` 保留，但 **`CollectionStatisticsVo` 去掉 `collectionRate` 字段**；
- `SysRole` 需初始化新增 role_code（后期种子数据阶段再补）：
  - `LEADER`（公司领导）
  - `CHIEF_ENGINEER`（总工）
  - `DISCIPLINE_HEAD`（专业主管）
  - `FINANCE`（财务）

- 不建议现在拆 `approval_records` 为多张表：保留单表 + `biz_type_ext` 即可；
- 不建议把 `output_value` 改成"按季度"新表：已有字段全部可复用，新增 `quarter` + 新增 `dist_type` 更经济；
- 工资明细 / 工资管理（按笔记要求）**暂不建表**，等绩效还原稳定后再引入。

- `GET /report/dashboard`：
  - 统计卡片去掉回款率；
  - 增加 `bidsPending`（投标待审批数）、`acceptancePending`（阶段性验收待审批数）；
  - "关键项目"排序口径由合同额改为**综合分**（合同额×60% + 已确认产值×40%），可选。
- 新增 `GET /report/personnel-quarter-summary`：**人员分配汇总表（季度）**，支持按 `quarter` 过滤；字段：`userId / realName / projectCount / allocAmount / completionAmount / leaderShare / companyShare`。

### 5.3 `OutputValueController`

- `POST /output-value/create`：
  - 入参增加 `quarter`、`subsidyAmount`（公司补贴）；
  - 分配明细 DTO 增加 `allocRatio` / `completionRatio` / `distType`；
  - 后端计算：
    - `companyReserve = totalAmount × 40%`
    - 个人金额 = `totalAmount × 60% × allocRatio × completionRatio`
    - 降档差额（8.06% - 实得）归为 `leaderExtra`
    - 离职成员未发金额归为 `otherAmount`
  - 保存前做**守恒校验**：`companyReserve + Σ人员金额 + leaderExtra + otherAmount = totalAmount`。
- `PUT /output-value/pay/{id}`：语义改为"确认完成"，前端按钮文案同步。

submit(bizType, bizId, firstApproverId)

queryChain(bizType, bizId)

- 终审通过时更新业务主表状态；
- 驳回时写一条终止记录。

## 八、风险与注意事项

1. **产值口径切换的数据回填**：现有表里 `output_value.status=3` 的记录含义会变，切换前需把旧数据批标为"历史口径"，避免误算。可加迁移字段 `legacy_flag`。
2. **审批链兼容**：`approval_records.inspection_form_id` 字段名偏业务化，扩展 `biz_type_ext` 即可，暂不改名以避免改动面过大。
3. **金额守恒**：新分配公式容易出现小数误差（8.06%、4% 与 40% 交叉），建议统一用 `BigDecimal.setScale(2, HALF_UP)`，并在 Service 层做守恒断言（Σ ≠ total 则报错）。
4. **离职判定**：`ProjectMember` 当前没有 `status`，建议加 `is_active tinyint`（0-离职/1-在职），分配单下单时快照到 `output_value_distribution.is_active`。
5. **季度字段格式**：统一 `YYYY-Qn`，前端做下拉；后端根据 `project_stage` 的时间自动推导默认值。
6. **回款模块是否保留**：虽与产值解耦，但业务仍需要记录现金回流与凭证，建议**保留**只删"回款率"。
7. **OA 集成**：本轮不做。注意不要把考勤/请假等表硬塞进 `edifice-core`，建议未来以独立服务或模块接入。
