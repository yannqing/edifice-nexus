# [v0.3] OA 系统集成方案 — RuoYi-Vue-Flowable-Plus

> 目标：在 2 天内给 edifice-nexus 集成一套**纯开源可商用**的 OA 系统，**共用用户表**，覆盖常见人事 / 行政 / 财务审批流程，并支持移动端。
>
> 编写时间：2026-04-25
> 覆盖模块：OA 系统选型、用户共享方案、15 个流程落地、SSO 接入、移动端策略、风险与时间盒。

---

## 一、结论与选型

### 1.1 选型结论

**首推：`KonBAI-Q/RuoYi-Vue-Flowable-Plus`**（或同等效的 RuoYi + Flowable 组合）

| 要点 | 说明 |
| --- | --- |
| 许可证 | **Apache 2.0**，完全开源可商用，无企业版功能锁 |
| 后端技术栈 | Spring Boot 3 + MyBatis-Plus + Flowable BPM（与 edifice-core 同栈） |
| 前端技术栈 | Vue 3 + Element Plus（与 edifice-vision 的 Next.js 不同栈，**独立部署**） |
| 工作流引擎 | Flowable（Apache 2.0），自带 BPMN 流程 + 表单设计器 |
| 移动端 | `RuoYi-App`（uni-app，MIT），可打包 iOS/Android 原生壳或纯 H5 |
| 数据库 | MySQL（与 edifice 同实例不同 schema，降低运维成本） |

### 1.2 为什么不选其他

| 候选 | 否决理由 |
| --- | --- |
| JeecgBoot | 低代码表单设计器 / 高级报表**企业版收费**，违反"纯开源"约束 |
| Snowy V2 | MIT 纯开源，功能齐全，但社区规模 / 插件生态显著小于 RuoYi，后续踩坑支持弱 |
| 钉钉 / 企业微信 | 不是开源；数据在第三方；但**考勤打卡部分**仍推荐用它们的 API（见 §4.3） |
| 自建 OA on edifice | 15 个流程的表单 + 流程图自建需 1–2 周，不满足"1-2 天"时间盒 |

### 1.3 不变式

- edifice-core **不动现有表和业务**
- 原有 `ApprovalFlowService` **继续服务于** 项目文件 / 验工 / 验收 / 投标 / 产值 等业务审批
- OA 只承担文档中 §三 列出的 15 个"标准化人事行政财务流程"
- 两套系统通过 **SSO + 用户同步**共享同一套账号

## 二、架构与用户共享方案

### 2.1 架构拓扑

```
┌────────────────────────────────────────────────────────┐
│                 浏览器 / 手机 H5                        │
└──────────────────────┬─────────────────────────────────┘
                       │
          ┌────────────┴────────────┐
          │                         │
          ▼                         ▼
  edifice-vision (Next.js)    ruoyi-vue (Vue 3)
  edifice 项目管理前端          OA 前端
  :3000                         :8080
          │                         │
          ▼                         ▼
  edifice-core (Spring Boot)  ruoyi-flowable (Spring Boot)
  :8081                         :8088
          │                         │
          └─────── MySQL ─── MySQL ─┘
             edifice_db      oa_db
                  ▲          ▲
                  └── JWT 共享密钥 + Webhook 同步
                      （edifice 为用户真源）

移动端:
  RuoYi-App (uni-app)  ───→  ruoyi-flowable
  （H5 或 App 打包）         走相同 SSO
```

### 2.2 用户共享方案：**SSO + 单向镜像（方案 A）**

**选择理由**：1-2 天时间盒内最合身；后续若要扩展再升级到 Casdoor 方案 B。

**核心原则**：
- **edifice 是用户唯一真源**（密码、角色、组织架构都存 edifice）
- OA 端的 `sys_user` 表只作**镜像**，不存密码
- 登录入口统一在 edifice；点击"办公 OA"菜单时由 edifice 签发 **共享 JWT** 带给 OA

#### 2.2.1 数据库布局

| 库 | 表 | 用途 |
| --- | --- | --- |
| `edifice_db.sys_user` | 原表 | 用户真源，所有字段齐全 |
| `oa_db.sys_user`（改造） | 镜像表 | 字段精简：`user_id`（外键到 edifice）/ `username` / `dept_id` / `is_delete` |
| `oa_db.*` 其他表 | 流程 / 表单 / 业务单 | Flowable 原生表 + 15 个业务表 |

#### 2.2.2 同步方向

- **edifice → OA（单向）**：用户 create / update / delete 时由 edifice 侧 webhook 推到 OA 的 `/system/user/sync` 接口
- OA 禁止自己改用户（管理页关闭，或改成只读）

#### 2.2.3 SSO 交互时序

```
用户在 edifice 侧边栏点 "办公 OA"
   ↓
前端 GET /auth/oa-sso-token  （edifice-core）
   ↓
后端用 OA 共享密钥签发 JWT（含 userId / username / exp）
   ↓
前端 window.open("https://oa.example.com/?ssoToken=xxx")
   ↓
OA 前端拿到 token，存 localStorage，调 OA 后端 /login/sso
   ↓
OA 后端用共享密钥验签，查镜像表 sys_user，建立 session
```

#### 2.2.4 改造 OA 的点

- 登录模块：增加 `/login/sso` 接口，只验 JWT 不校密码
- 用户管理 UI：关闭新增 / 删除用户按钮；把"修改密码"跳到 edifice
- 接收 webhook：`/system/user/sync` 接收 edifice 推送

## 三、15 个流程落地清单

全部用 **Flowable 表单设计器**在浏览器里配置，不写 Java 代码。按工作量分档：

### 3.1 纯审批流程（单表单 + 审批链）— ⭐ 0.5 小时 / 个

| 流程 | 字段 | 审批链建议 |
| --- | --- | --- |
| 请假 | 请假类型（事假/病假/年假） / 起止时间 / 天数（自动算）/ 事由 | 部门主管 → HR（>3 天加老板） |
| 出差 | 目的地 / 起止日期 / 同行人 / 预算 / 事由 | 部门主管 → 财务（预算审批） |
| 补卡 | 日期 / 时段 / 原因 | 部门主管 |
| 外出申请 | 外出时间 / 目的地 / 事由 / 预计返回 | 部门主管 |
| 转正申请 | 入职日期 / 转正日期 / 自评 / 期望 | 直接主管 → HR → 总经理 |
| 离职 | 离职原因 / 最后工作日 / 交接人 | 直接主管 → 部门总监 → HR |
| 通用审批 | 标题 / 内容 / 事由（自由文本） | 发起人选审批人（动态） |

### 3.2 带附件 / 关联业务 — ⭐⭐ 1 小时 / 个

| 流程 | 关键字段 | 业务表 |
| --- | --- | --- |
| 用车申请 | 用车时间 / 目的地 / 乘车人数 / 用途 / **附件**（行程单等） | 可选 `oa_vehicle` 车辆库 |
| 公文审批 | 公文标题 / 正文 / **正文附件** / 密级 / 紧急程度 | 复用 Flowable 附件能力 |
| 开票申请 | 开票金额 / 开票抬头 / 税号 / 开户行 / 开票项目 / **合同附件** | 可关联 edifice 的 `contract` |

### 3.3 带业务数据表 — ⭐⭐⭐ 1.5 小时 / 个

| 流程 | 关键字段 | 新建表 |
| --- | --- | --- |
| 用章申请 | **印章**（下拉，关联印章库） / 用章文件（附件）/ 事由 / 使用次数 | `oa_seal` 印章库（预录入） |
| 采购申请 | 采购明细（物品 / 数量 / 单价 / 小计 行项目）/ 总金额 / 供应商 / 预计到货 | `oa_purchase_item` 明细表 |
| 费用报销 | 报销明细（日期 / 类型 / 金额 / 发票号 / 附件 行项目）/ 总金额 / 报销账户 | `oa_expense_item` 明细表 |
| 对外付款 | 收款方 / 收款账户 / 付款金额 / 付款事由 / **合同附件** / 关联合同 | 可关联 edifice 的 `contract` |

### 3.4 考勤（单独处理）— ⭐⭐⭐⭐

> **考勤的定位打卡 + 拍照不是审批流**，是数据采集。Flowable 不适合做。

**推荐实现路径**：

**路径 A — 对接钉钉 / 企业微信考勤 API（强烈推荐）**
- 公司如已使用钉钉 / 企微，直接用它们的考勤：定位精度、拍照压缩、离线补传、异常申诉都已成熟
- edifice 或 OA 侧做 1 张 `attendance_record` 镜像表，每天定时从钉钉 API 拉数据回来做统计
- **工作量**：1 天

**路径 B — 自建考勤模块（仅当 A 不可行）**
- uni-app 移动端加两个页面：`打卡页`（调用 GPS + 相机）/`打卡记录页`
- OA 后端加 `oa_attendance_record` 表（用户 id / 打卡时间 / 经纬度 / 地址 / 照片 URL / 类型 上班/下班）
- 涉及：地理围栏 / 照片上传 / 异常定位检测
- **工作量**：2-3 天

本文档**推荐路径 A**，时间盒才能守住。

### 3.5 补卡与考勤的关系

补卡走 OA 审批流（§3.1），审批通过后由 OA 回写 edifice / 钉钉的考勤记录表，标记为"补卡通过"。

## 五、集成技术细节

### 5.1 edifice-core 侧改动

**新增文件**：

- `controller/OaSsoController.java`
- `service/OaUserSyncService.java`
- `config/OaConfig.java`（读取共享密钥 / OA 回调 URL 等）

**关键接口**：

```java
/** 用户在 edifice 点"办公 OA"时调这个接口拿 token */
@GetMapping("/auth/oa-sso-token")
public BaseResponse<String> getOaSsoToken(HttpServletRequest request) {
    SysUser loginUser = jwtUtils.getUserFromToken(request.getHeader("token"));
    // 用 OA 共享密钥签发一个短 TTL（5 分钟）的 JWT
    String token = oaSsoService.signToken(loginUser.getUserId(), loginUser.getUsername());
    return ResultUtils.success(Code.SUCCESS, token);
}
```

**用户同步**：在 `SysUserServiceImpl.createUser / updateUser / deleteUser` 结尾挂 hook：

```java
@Transactional
public void createUser(SysUserCreateDto dto) {
    // ... existing logic ...
    oaUserSyncService.pushUser(user, "create");  // 异步发送到 OA
}
```

**同步 payload**（仅必要字段）：

```json
{
  "event": "create",
  "userId": "12345",
  "username": "zhangsan",
  "realName": "张三",
  "email": "zs@co.com",
  "phone": "13800000000",
  "deptId": "10",
  "status": 1
}
```

**配置**（`application.yml`）：

```yaml
oa:
  enabled: true
  sso-secret: ${OA_SSO_SECRET:change-me}   # 与 OA 共享
  sync-endpoint: http://oa.example.com/api/system/user/sync
  sync-api-key: ${OA_SYNC_KEY:change-me}   # 同步接口鉴权
```

### 5.2 OA 侧改动

**登录接口新增**：

```java
@PostMapping("/login/sso")
public AjaxResult loginBySso(@RequestBody SsoLoginDto dto) {
    // 1. 用共享密钥验 dto.token
    Claims claims = JwtUtil.parse(dto.getToken(), ssoSecret);
    Long userId = claims.get("userId", Long.class);
    // 2. 查镜像表
    SysUser user = userService.selectByEdificeUserId(userId);
    if (user == null || user.getDelFlag() == 1) return AjaxResult.error("用户不存在");
    // 3. 签发 OA 自己的 token（与普通登录一致）
    return AjaxResult.success(tokenService.createToken(user));
}
```

**接收同步**：

```java
@PostMapping("/system/user/sync")
public AjaxResult syncUser(@RequestHeader("X-API-Key") String apiKey,
                           @RequestBody UserSyncDto dto) {
    if (!Objects.equals(apiKey, config.getSyncApiKey())) return AjaxResult.error(403);
    userService.upsertFromEdifice(dto);  // 幂等 upsert
    return AjaxResult.success();
}
```

**用户表改造**（`ALTER TABLE`）：

```sql
ALTER TABLE sys_user
  ADD COLUMN edifice_user_id BIGINT NULL COMMENT 'edifice sys_user.user_id',
  ADD UNIQUE KEY uk_edifice_user (edifice_user_id),
  MODIFY COLUMN password VARCHAR(100) NULL COMMENT '镜像用户不存密码';
```

**UI 屏蔽**：
- `vue/src/views/system/user/index.vue` 隐藏 "新增" / "删除" 按钮（或基于 `isSsoMirror` 动态判断）
- "修改密码" 改为外链跳转 `edifice.example.com/profile/password`

### 5.4 Nginx 反代示例

```nginx
server {
  listen 443 ssl;
  server_name example.com;

  # edifice 主应用
  location / {
    proxy_pass http://edifice-vision:3000;
  }
  location /api/ {
    proxy_pass http://edifice-core:8081/;
  }

  # OA 系统（同域子路径方案，避免 iframe 跨域 cookie）
  location /oa/ {
    proxy_pass http://ruoyi-vue:8080/;
    proxy_set_header X-Forwarded-Prefix /oa;
  }
  location /oa/api/ {
    proxy_pass http://ruoyi-flowable:8088/;
  }
}
```

**提示**：OA 前端必须支持 `publicPath=/oa/`（Vue 的 `vue.config.js` 或 Vite 的 `base` 配置），否则静态资源 404。

### 5.5 移动端策略

| 场景 | 方案 |
| --- | --- |
| 员工日常审批 / 查询 | 浏览器打开 `https://oa.example.com`，RuoYi-App 的 H5 响应式已经够用 |
| 需要"原生 App 体验" | 用 RuoYi-App（uni-app）的源码，在 HBuilderX 一键打包 Android / iOS 壳 |
| 考勤打卡 | 用钉钉 / 企业微信原生 App（路径 A） |
| SSO 一致性 | 移动端进入时带上 edifice 签发的 SSO token（可用短链或自定义 URL Scheme） |

## 七、风险与注意事项

### 7.1 SSO 共享密钥泄露

- **影响**：攻击者可伪造任意用户登录 OA
- **缓解**：
  - 密钥至少 64 字符，通过环境变量而非配置文件注入
  - JWT 签发 TTL 设为 **5 分钟**（只够完成跳转）
  - OA 侧验 JWT 时同时校验 `iss` / `aud`
  - 密钥每季度轮换一次

### 7.2 用户同步不一致

- **症状**：edifice 改了手机号，OA 里还是旧的
- **缓解**：
  - 同步用异步队列（或 Spring 事件），失败有重试
  - 建 `oa_user_sync_log` 表记录每次推送结果
  - 每天定时全量 diff 补偿

### 7.3 考勤选型漂移

- **风险**：今天选钉钉，明天公司换企微，得重做
- **缓解**：
  - 在 edifice 加一层 `AttendanceProvider` 接口抽象
  - 具体实现 `DingtalkProvider` / `WeWorkProvider` 可切换

### 7.4 移动端审批的网络抖动

- **症状**：户外 4G 弱时提交审批多次
- **缓解**：
  - 所有提交接口做**幂等键**（`clientRequestId`）
  - 客户端超时后先轮询状态再重试

### 7.5 流程版本迁移

- **症状**：改了请假流程定义，老数据怎么办
- **缓解**：Flowable 原生支持流程版本；已发起的实例保留旧版本运行，新发起的走新版本

### 7.6 法务 / 合规

- **印章 / 合同 / 财务相关流程**建议做**操作日志 + 水印**（Flowable 审计日志 + 附件加水印），以备审计
